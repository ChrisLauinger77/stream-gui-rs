# Engineering guide for Stream GUI RS

Stream GUI RS is a cross-platform desktop frontend for browsing Twitch and watching streams through external
Streamlink and a separately installed player. The stack is Tauri 2, Rust, React, TypeScript and Vite;
targets are Linux, macOS and Windows. Twitch supplies identity and browsing data; Streamlink handles media.

```text
Twitch → Rust auth / Helix / cache → typed Tauri IPC → React
React playback action → typed IPC → Rust services / Supervisor → Streamlink → player
```

This guide defines engineering rules and invariants. Read the relevant code and detailed documentation
before changing a contract; do not infer implementation from a phase number in a task description.

## Ownership and module map

Rust owns authoritative native/backend state: OAuth credentials and lifecycle, secure storage, Helix HTTP,
rate limits, cache freshness, application settings, effective playback configuration, executable discovery,
command construction, sessions, child lifecycles, bounded diagnostics and native desktop operations.

React owns presentation and interaction: navigation, forms/drafts, tabs, dialogs, focus, pending-request
guards and bounded navigation snapshots. Backend snapshots may be displayed in React; they do not transfer
authority to it. If behavior affects credentials, persistence, native resources, external processes or
authoritative Twitch state, it probably belongs in Rust. Theme preference also persists through Rust settings; React applies the accepted snapshot.

## Typed IPC and native permissions

- Use only the closed command map in `src/lib/ipc.ts` for frontend invocation. Handlers delegate to domain
  services; Rust validates all frontend inputs.
- Express intent with actual commands such as `streamlink_launch`, `streamlink_stop`, `streamlink_restart`,
  `playback_settings`, `save_playback_settings`, `channel_settings`, `save_channel_settings`,
  `open_channel_chat` and `auth_open_verification`.
- Never add generic `execute_program`, `open_arbitrary_url`, `http_request`, `set_setting(key, value)` or
  `read_credentials` APIs.
- Return intentional safe DTOs and typed `AppError` codes, not provider objects, raw response bodies,
  credentials or internal handles.
- Rust DTOs derive `TS`. After changing them, run `npm run bindings`; commit `src/lib/generated.ts` with the
  Rust change. Do not hand-edit generated DTOs.
- Keep command registration in `src-tauri/src/desktop/mod.rs`, the manifest in `src-tauri/build.rs`, the
  frontend map, generated application permissions under `src-tauri/permissions/autogenerated/`, and
  `src-tauri/capabilities/main.json` aligned. Do not broaden capabilities to avoid fixing a missing explicit
  entry.
- Capabilities belong to the local main window. Preserve the CSP in `src-tauri/tauri.conf.json`: no direct
  Twitch API access from the webview; remote images are restricted to validated Twitch CDN HTTPS URLs.

## Security and authentication

- Access/refresh tokens and the secret device code stay in Rust; never add them to frontend DTOs, ordinary
  logs, diagnostics, settings or process arguments. The displayed Device Flow user code and public session
  marker are intentional safe DTO fields, not access credentials. Do not record real sign-in codes.
- OS storage is the only production token persistence: Keychain, Credential Manager or Secret Service. No
  plaintext or automatic memory fallback. Preserve `CredentialVault` serialization on blocking workers, the
  local credential-entry lock and zeroizing token buffers; no token `Debug`/`TS` derives.
- Preserve startup/hourly validation, coordinated refresh and logout deletion. Confirm secure deletion
  before dispatching one-use refresh; save the replacement before validation. Never blindly retry an
  exchange with an uncertain outcome.
- Auth work is service-owned: dropping an IPC caller must not abandon rotation or allow a credential write
  after logout. Normal shutdown drains active work.
- There is no Twitch client secret. Public client-ID precedence is runtime `TWITCH_CLIENT_ID` override → ID
  embedded from `TWITCH_CLIENT_ID_BUILD` → error. Explicit empty/invalid values fail, without silent
  fallback or value echoing.
- `build.rs` requires the embedded ID for non-debug profiles and Tauri `custom-protocol` builds, including
  packaged debug/no-bundle builds. Runtime configuration cannot bypass that guard. Public IDs may be in the
  binary; OAuth configuration never goes into React, `VITE_` variables or settings.
- OAuth/Helix errors use safe categorized text. Never return or log provider bodies, token-bearing
  URLs/headers or raw credential-store errors. Normal UI uses fixed messages in `src/browse/errors.ts`; do
  not stringify unknown IPC errors.
- `auth_open_verification` takes no URL and uses the validated Twitch activation URL.
  `open_channel_chat` accepts only broadcaster/session IDs and constructs a fixed Twitch popout URL from
  fresh, session-bound identity. Keep native opening restricted to these validated destinations. Linux GIO
  dispatch reaps browser launchers; preserve the isolated regression and safe errors.
- Do not commit real credentials, account captures, personal local paths, `.env` files or credential
  exports. Keep generated builds, bundles, dependencies and diagnostic logs out of Git; preserve
  `.gitignore` protections.

## Authentication session isolation and Helix

A logical Twitch operation belongs to the authentication session under which it began: request A → logout →
login B must never resume the original request as B. Preserve this across retries, lease reacquisition,
pagination, search, batching, enrichment and account-specific cache access, including re-login to the same
user.

- Reuse `HelixClient`, `TwitchHttp`, their rate coordinator and bounded cache. No React Twitch fetches,
  independent clients/budgets or frontend cache TTLs.
- Preserve `RequestSession` binding, lease cancellation and generation checks. The public session ID selects
  a Rust-validated session; it grants no authority. Add deterministic regressions when changing these
  concurrency boundaries.
- Respect opaque cursor pagination and bounded ID batches. Fetch one requested page at a time; no automatic
  exhaustive crawling. Keep stream IDs distinct from broadcaster/user IDs, login names and display names.
- A failed/incomplete API response cannot establish offline status. Preserve explicit network/error,
  unknown, stale, partial and unavailable semantics.
- Cache only typed public data, scoped to the original session/account. Keep cache/body/query/concurrency
  limits and finite retry policies intact.
- Preserve suspend-aware deadlines in `time.rs`; backward wall-clock changes must not revive cached data or
  extend established auth/rate deadlines.

## Streamlink, players and sessions

- Streamlink 8.0+ and players remain external dependencies. Orchestrate them; do not reimplement media
  transport or introduce download/profile frameworks.
- Launch IPC takes broadcaster ID, auth-session ID and optional quality. Rust resolves fresh live identity
  and constructs the canonical Twitch channel URL. Recheck auth after discovery/probing and at spawn;
  metadata is never command text.
- Use executable + argv, never a shell. Keep `build_command` pure and testable. Explicit executable
  selection is a local trust decision, not a sandbox. Preserve `--no-config`, `--no-plugin-sideloading` and
  the `--` argument boundary.
- Player arguments are bounded literal entries. Preserve `encode_player_arguments` for Streamlink's
  Formatter/`shlex.split` boundary, including braces, quotes, empty strings and the owned `{playerinput}`
  placeholder. Paths are separate argv.
- Modes are Streamlink default, mpv, VLC and custom. Keep OS-specific preset differences; macOS VLC must not
  receive Linux/Windows `--no-one-instance`.
- Policies are **Source** (`best`), **High** (720p30), **Medium** (540p30), **Low** (360p30) and **Audio**
  (`audio,audio_only`). High/Medium/Low include an unfiltered-source fallback; they are preferences, not
  guaranteed resolution caps.
- `Supervisor` is authoritative. Running means the child exists, not verified video. Never derive lifecycle
  success/failure from human-readable log lines.
- Sessions are independent and addressed by explicit IDs. Stop is idempotent for retained IDs. Restart uses
  the observed generation, reaps the old run before replacement, rejects stale/overlapping requests and
  respects Stop/shutdown cancellation. Do not turn repeated restart requests into additional launches.
- Preserve service-owned operations, reservation cleanup, concurrent pipe draining and child reaping. Signal
  under the registry lock; wait outside it. Keep blocking OS calls on blocking workers, preserving
  credential-vault serialization.
- Preserve bounds: eight active/reserved sessions, sixteen retained snapshots, 200 log entries/session and
  2,048 input bytes/line. Overlong/credential-shaped output is suppressed and controls stripped while pipes
  continue draining. Redaction is not a universal detector for arbitrary custom-executable output.
- Navigation, webview reload and logout leave streams running; existing sessions remain
  stoppable/restartable. New browsing launches require authentication.
- Window close/Quit stops owned playback and exits. Unix process groups and Windows kill-on-close jobs own
  descendants; intentionally detached players escape that boundary. Do not imply forced termination
  guarantees normal cleanup.

## Settings and launch configuration

- `SettingsStore` owns strict version 3 settings: global Streamlink/player/quality/chat/theme preferences
  and sparse channel overrides, under Tauri's app config directory. Preserve atomic replacement, in-memory
  migrations from this app's versions 1 and 2, and rejection of malformed/unknown schemas without overwrite.
  Files are bounded to 256 KiB and channel overrides to 1,000 records.
- Precedence is global defaults → optional channel overrides → optional request quality → immutable
  effective snapshot in `LaunchSpec` and the session. `quality: null` inherits; resolve only in Rust.
- Channel overrides use stable positive decimal broadcaster IDs. Quality/chat null means inherit; false
  explicitly disables chat. Remove fully inherited records. These local preferences apply across accounts;
  they never grant authentication or playback authority.
- Saving settings does not mutate running processes. Explicit restart resolves current settings, retaining
  trusted session identity without a fresh Helix lookup. Chat opens once per enabled launch/restart;
  generation-checked browser errors must not hide or fail playback.
- Preserve configured paths/symlinks; resolve their targets at use. Failed/unsupported Streamlink probes or
  invalid player paths must not replace valid preferences. Global updates preserve channel records; path
  probes update only the path. React holds editable drafts and displays Rust effective previews.

## Frontend and desktop UX

- Prefer composition and existing hooks/components over giant configurable components, unnecessary global
  state or a new state-management framework.
- Navigation snapshots are not a Twitch cache: preserve session-keyed workspace replacement, twelve retained
  visits/snapshots and ten pages/300 items per view. Label retained results; only Rust determines data
  freshness.
- Guard late search/account/poll responses with the existing generations/unmount checks. UI pending keys
  describe requests, never authoritative process state.
- Preserve keyboard activation, Back scroll/focus restoration, and pagination focus without stealing focus
  when the user has moved elsewhere.
- Treat loading, empty, error, offline, unknown and stale states separately. Preserve image
  dimensions/placeholders and retry failed images after accepted refreshes without resetting already-loaded
  images on ordinary rerenders.
- Keep the UI compact, fast, desktop-oriented and informative without clutter. Preserve System/Light/Dark
  themes, CSS tokens, readable contrast and visible focus. Avoid mobile-sized cards, excessive whitespace,
  gratuitous animation, decorative glass/gradients, unnecessary containers and imitation of the Twitch
  website.
- No preference authority lives in localStorage. Theme follows the Rust snapshot and native
  `prefers-color-scheme`. App-local shortcuts reuse navigation/focus and pause in inputs, editable content,
  composition/repeats and modal dialogs; preserve Control versus Command conventions.

## Cross-platform and dependency discipline

- Consider Linux/WebKitGTK, macOS/WKWebView and Windows/WebView2 for every change; do not rely on
  Chromium-only APIs. Keep genuine OS differences in native adapters.
- Linux: respect XDG/application paths, executable bits, desktop PATH differences and the user D-Bus/Secret
  Service session. No insecure fallback when locked/absent.
- macOS: account for GUI PATH, Apple Silicon/Intel install locations, application bundles and Keychain
  prompts. Do not hard-code one developer's installation.
- Windows: support native `.exe` paths, Program Files, spaces/Unicode, hidden consoles and suspended spawn →
  job assignment → resume. Reject script wrappers.
- Before adding a crate/package, check the standard library and existing stack, justify the need and avoid
  large frameworks for small tasks. State/UI frameworks, shell wrappers and generic settings frameworks need
  a concrete requirement.
- Keep Twitch-specific concepts explicit until another actual service justifies abstraction. Do not add
  speculative interfaces for hypothetical features.

## Tests and validation

- Prefer behavior/contract assertions to implementation details or broad snapshots. A bug fix normally
  includes a regression proving the failure and smallest fix. Use deterministic coordination for
  concurrency, cancellation and lifecycle races.
- Reuse `src-tauri/tests/process_lifecycle.rs` and its native executable
  `src-tauri/tests/support/fake_streamlink.rs`; mocks alone cannot prove pipe, process-tree or reaping
  behavior. `test-support` is for checks, not app builds.
- Backend tests live alongside modules; HTTP fixtures use `src-tauri/src/test_http.rs` and
  `src-tauri/tests/fixtures/helix/`. `src-tauri/tests/client_id_build.rs` executes the actual build script
  guards.
- Frontend behavior tests are `src/app/App.test.tsx` and `src/app/Browsing.test.tsx`; CSS contracts are
  `src/styles/base.test.js`. Use existing Vitest/jsdom, React `act`, fake timers and deferred responses.
- Normal tests/CI use synthetic credentials and local HTTP, never real Twitch credentials or the user's
  secure-store entries. HTTP tests need loopback access. Temporary adversarial probes may aid review; retain
  regressions for confirmed bugs.

Run commands from the repository root. Setup is `npm ci`, stable Rust and Node.js 22.22.2+, 24.15.0+, or
26+ (CI uses Node 24),
plus the native prerequisites in README. There is one Cargo package at `src-tauri/Cargo.toml`, not a root
Cargo workspace.

Fast iteration: run the affected tests; for frontend work use `npm run typecheck` and `npm test`. For Rust,
run formatting and the backend test command below (narrow to relevant tests during iteration).
Documentation-only changes need path/command/claim review and `git diff --check`, not a native rebuild.

Full validation for application changes follows `.github/workflows/ci.yml`:

```sh
npm run build
npm test
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo test --locked --manifest-path src-tauri/Cargo.toml --no-default-features --features test-support
cargo check --locked --manifest-path src-tauri/Cargo.toml --all-targets --features test-support
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets --features test-support -- -D warnings
TWITCH_CLIENT_ID_BUILD=ciCompileOnlyPublicClient123 npm run tauri build -- --debug --no-bundle --features custom-protocol --ci
git diff --check
```

On Linux, also run `cargo test --locked --manifest-path src-tauri/Cargo.toml --test linux_browser_open --features test-support`. It isolates XDG associations and uses the native fixture; it must never open the real browser. The `linux_startup` regression is ignored in headless runs; explicitly run it with `-- --ignored` in a graphical session after changing native setup/error handling.

`npm run build` includes TypeScript checking. The local build command above uses a synthetic public ID for
compilation only. CI uses the repository secret `TWITCH_CLIENT_ID_BUILD` when available, otherwise the
synthetic ID for non-publishing checks. Never use that fallback in a release workflow. For PowerShell, set
the environment variable separately as documented in `docs/authentication.md`. `--no-default-features` omits
desktop/WebView linkage, not all native dependencies. There is no configured ESLint/Prettier or
Markdown-lint command; do not invent one.

Manual verification is separate: auth changes need relevant real Device Flow, storage/restart/logout checks;
playback changes need real Streamlink/mpv/VLC, actual video/audio, Stop/Restart, concurrent sessions and
shutdown checks. Desktop changes need browser opening, themes and keyboard checks in the native webview.
Report exactly what was automated, manually observed and not run on each platform; a CI matrix,
cross-compilation or process status does not prove native behavior.

## Change workflow and style

- Inspect status, relevant implementation and docs before editing; preserve user changes. Fix root causes
  with focused tests, not opportunistic refactors.
- For features: choose the ownership layer, reuse services, minimize IPC, protect security/session
  boundaries, test and perform relevant native smoke checks. Update docs when behavior or architecture
  changes. Optional review suggestions are not authorization to implement unrelated improvements.
- Use rustfmt and existing Rust naming. Frontend code uses two-space indentation, semicolons and
  predominantly double-quoted strings, with compact JSX/CSS; match nearby code and avoid formatting
  unrelated files. Comments must be English and explain why; preserve safety reasoning around native
  `unsafe` operations.
- Prefer small logical commits; inspect the final diff, run appropriate validation and report gaps honestly.
  When committing, use Conventional Commits with a short lowercase imperative subject. Aim for a clean tree
  without discarding others' work; report any remaining changes. Never rewrite history, push or publish
  unasked.
- A user request to `create release X.Y.Z` authorizes the complete documented release sequence: update every
  version location with `npm run release:version -- X.Y.Z`, validate and review the result, commit and push the
  preparation to `main`, wait for Desktop checks and CodeQL, then create and push the annotated `vX.Y.Z` tag.
  Do not request separate confirmation for those steps. The tag-triggered workflow owns package creation and
  GitHub Release publication.

## Agent checklist

- **Before editing:** read relevant code/docs and status; identify ownership, security/session implications
  and cross-platform constraints.
- **While editing:** keep IPC narrow and authority in Rust; reuse existing services; preserve bounds and
  lifecycle; add focused tests with behavior changes.
- **Before completion:** run relevant/full checks as appropriate; inspect diff; check for secrets/log
  leakage and unintended files; verify generated DTOs and docs; report manual/platform gaps and the final
  working-tree/commit state.
