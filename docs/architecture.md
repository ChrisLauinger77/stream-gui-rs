# Stream GUI RS architecture through Phase 3

```text
React (browsing + Watching + settings, public DTOs only)
    ↓ typed Tauri IPC
Rust backend
    ├── Twitch device authorization / validation / refresh
    │      └── CredentialVault → platform CredentialStore
    ├── Browsing queries / safe application DTOs
    │      └── Helix endpoint methods / typed models
    │      ├── bounded cache / pagination / ID batching
    │      └── shared Twitch HTTP pool / rate coordinator
    ├── versioned settings
    └── Streamlink discovery / probe / session supervision
            ↓ native process + argument array, never a shell
        Streamlink
            ↓ default / mpv / VLC / custom player
        external player
```

The application identity is `io.github.stream-gui-rs`; Tauri derives application directories from it. Secure credentials use the separate service `io.github.stream-gui-rs.oauth`, keyed by the public Twitch client ID. The pre-release rename intentionally starts with new settings and a fresh login. Twitch/Helix modules and IPC contracts retain their existing names and ownership.

## Ownership

`domain` holds errors, request DTOs and the service coordinator. `streamlink`, `twitch`, `twitch_http`, `helix`, `config`, `credentials`, `diagnostics`, and `platform` have no Tauri dependency. `desktop` composes services, resolves the platform application directory, opens the window, and handles shutdown. `commands` contains only adapters. The optional `desktop` Cargo feature allows backend tests without WebView libraries.

The frontend shell and authentication hook live in `app`; `browse` owns view navigation, query snapshots, shared stream/image presentation, search and details; `lib` owns generated DTOs and typed IPC; `styles` owns theme tokens. `playback` holds the snapshot/request hook and quality presentation; `features` holds the shared Watching and playback settings components, plus authentication diagnostics. React state contains only UI inputs and backend snapshots. There is no frontend OAuth client or token persistence. There are no placeholder stores, assets, or background modules; background auth and process tasks remain with the services that own their lifecycle.

## IPC

Rust DTOs derive `TS` and generate `src/lib/generated.ts`. A checked-in equality test enforces the contract. `src/lib/ipc.ts` is the only frontend `invoke` entry point and accepts a closed set of named operations and typed request objects. Rejections carry `{code, message}`. External provider bodies never become errors or logs.

Commands cover backend diagnostics, probe/save, playback settings get/update, player discovery, launch, stop, generation-checked restart, session snapshots, auth status/login/cancel/logout/validate/refresh/account, opening the current Twitch verification link, and the eight browsing operations listed below. No frontend-selected shell, arbitrary argv, generic filesystem API or arbitrary browser URL is exposed. Selecting a custom Streamlink executable is an intentional local trust decision: version probing is validation, not executable sandboxing.

The main window has an explicit command allowlist generated by Tauri's application manifest. Remote origins get no capability. Production CSP blocks third-party scripts, direct web API connections, frames, and form submission. Only Rust contacts Twitch OAuth and Helix. Safe account and browsing DTOs permit HTTPS images from `static-cdn.jtvnw.net`; the CSP allows only that image origin in addition to local assets. The browser-opening command accepts no URL argument and checks the provider's HTTPS Twitch activation URL.

## Streamlink sessions

The reviewed Phase 0 `Supervisor` is the sole process registry. Phase 3 adds typed settings/command construction, identity resolution and restart generations to it; it does not introduce a second process owner.

```text
Watch(broadcaster ID, public auth-session ID, optional quality policy)
  → bounded service-owned playback operation
  → uncached Rust Helix live-identity lookup for that exact auth session
  → current validated settings + native executable discovery/version probe
  → LaunchSpec (resolved paths, trusted stream identity, selected policy)
  → pure CommandSpec (executable + argv vector, no process creation)
  → existing Supervisor → Streamlink → external player
```

The login alone constructs `https://www.twitch.tv/<login>` after ASCII channel-name validation. Display names, titles and categories are session metadata and never become command arguments. The service rechecks authentication after probing. Twitch stream ID, broadcaster ID, login and display name remain distinct. Existing session restart retains that identity without a new Helix lookup; it can therefore report offline or renamed-channel failure through Streamlink diagnostics. It never resolves a new account on behalf of an old request.

Discovery tries absolute PATH entries and common platform locations: Linux `/usr/local/bin`, `/usr/bin`, `/bin`, `~/.local/bin`; macOS additionally `/opt/homebrew/bin` plus mpv/VLC executables in system/user Applications bundles; Windows native `.exe` names under PATH, Program Files and Local App Data/Programs. A custom absolute path is the escape hatch. No interpreter/profile/download framework is involved. Explicit paths preserve the user's spelling/symlink in settings and resolve their current target for each use. Directories, non-executable Unix files and Windows script wrappers are rejected. Player discovery is independently testable without Tauri.

The version probe concurrently drains both pipes with bounded capture and a five-second deadline, killing/reaping on timeout. Production playback requires Streamlink 8.0+. The base argv is `--no-config --no-plugin-sideloading --loglevel info --player-verbose`, followed by optional player/quality flags and `--`, canonical channel URL, quality selection. `Command::new` receives the executable path separately; no shell command is composed. The only prototype URL/quality launch adapter is retained for Phase 0 native contract tests and is not reachable through IPC. OAuth tokens are not passed in argv, environment additions or configuration files.

| Policy | Positional selection | `--stream-sorting-excludes` |
| --- | --- | --- |
| Source | `best` | omitted |
| High | `high,best,best-unfiltered` | `>720p30` |
| Medium | `medium,best,best-unfiltered` | `>540p30` |
| Low | `low,best,best-unfiltered` | `>360p30` |
| Audio | `audio,audio_only` | omitted |

These follow the original app's policy model using current Streamlink syntax. The final unfiltered fallback deliberately permits a rendition above the nominal cap when needed. There is no rendition-discovery request/UI or automatic observer-driven relaunch.

Player modes are default (delegate discovery to Streamlink), mpv, VLC and custom. mpv adds `--keep-open=no --quiet`; VLC adds `--play-and-exit`, with `--no-one-instance` only on Linux/Windows because native macOS VLC does not support that option. Additional arguments are a bounded vector of literal strings, not shell text. Each entry has formatting braces doubled, is POSIX-single-quoted with embedded quotes escaped, and is joined for Streamlink's second parsing boundary (Formatter followed by `shlex.split`, including on Windows). An owned `{playerinput}` is always appended so a literal user string containing that text cannot suppress stdin. Executable paths are separate unquoted argv values. The supported transport is Streamlink's normal player stdin only. See [validation and upstream references](phase-3-validation.md).

Each session has a stable UUID, generation, trusted metadata, selected policy, process phase, timestamps, optional typed failure and bounded logs. A successfully spawned process is `running`; restart preparation is `starting`, and cleanup is `stopping`. Natural success or requested stop ends in `exited`; unexpected process failure ends in `failed`. Nonzero exit before three seconds is classified `startup_failed`, later exit `streamlink_exited`. This timing is diagnostic only: neither it nor `Starting player:` proves video rendering.

One task owns each child and two concurrent readers drain stdout/stderr. Stop signals under the registry lock, releases it before waiting, and is idempotent for retained IDs. Restart accepts the observed generation, reserves the same session, reaps the old child/readers, resolves current settings and then spawns the replacement. Stale generations and overlapping restart attempts are rejected. An external Stop increments a cancellation revision, preventing a pending restart from spawning; shutdown closes the registry. A dropped IPC caller cannot abandon production launch/restart work because the service task owns it. Dropping a lower-level restart future also releases its reservation. Replacement retains metadata/ID and bounded diagnostics with a restart marker; it never overlaps the prior generation.

Eight active/reserved sessions, eight outstanding playback operations and sixteen retained snapshots bound capacity. A terminal history entry cannot restart past active capacity. Only unreserved terminal snapshots may be evicted; unknown/evicted IDs return `not_found`. Spawn failures before a first child create no session; restart failures retain the session and a safe diagnostic. Starting channel A does not stop B. Requests always target explicit session IDs.

Per session, 200 log entries are retained. Individual lines are bounded to 2,048 input bytes; oversize lines are omitted while pipes continue draining. Invalid UTF-8 is replaced, terminal control characters are stripped, and common credential-related lines are suppressed. Logs are React text, available only within that session, and never persisted. An untrusted custom executable can still output arbitrary sensitive content; the filter is not a universal secret detector.

Unix children use a separate process group. Windows children start suspended and enter a kill-on-close Job Object before their primary thread is resumed, preserving the reviewed ToolHelp adapter and hidden-console behavior. Stop and normal parent exit clean up owned descendants and reap the direct child; readers are cancelled if inherited pipes remain open. Intentionally detached/custom external players are outside that ownership boundary.

Navigation, webview reload and Twitch logout do not stop already-owned sessions. Restart and Stop remain available after logout; new browsing launches require an authenticated session. There is no tray/background mode: main-window Close and application Quit enter the same shutdown coordinator, close service gates, signal every session, cancel pending restart, and await sessions, probes and authentication cleanup before exit. `kill_on_drop` and group/job ownership are backups. An uncatchable Unix app kill cannot guarantee cleanup; no process-recovery daemon is implemented.

## Authentication and settings

One Rust service serializes credential restoration, device polling, validation, refresh, and logout. An auth-only async mutex protects operations spanning HTTP and secure-store writes; it is independent of the playback locks. A separate watch snapshot makes `auth_status` immediately readable during network or keychain waits. Explicit cancellation signals the pending device request before waiting for the credential owner; late completion cannot reauthenticate after cancellation or logout.

Auth operations belong to service tasks, not to the lifetime of an IPC caller. Dropping a caller cannot abandon a token rotation or let a queued keychain write land after logout. Concurrent explicit validation/refresh calls share completed operation revisions; concurrent Helix 401s verify the original session before comparing credential generations and sharing one refresh. An internal access lease carries a secret token plus account/session/generation identity and cancellation; it is never serializable. Logout/revocation/shutdown cancel leases. A later login has a new session identity, so it cannot reuse an old account's cache entries or supply a replacement lease to an older logical Helix operation.

The Rust startup configuration resolves an explicit `TWITCH_CLIENT_ID` developer override before the public ID embedded from `TWITCH_CLIENT_ID_BUILD`. Missing or invalid startup configuration is an error before secure storage is opened. `build.rs` requires an embedded ID for non-debug Cargo profiles and Tauri `custom-protocol` builds, including packaged debug builds; a runtime override cannot satisfy that requirement. The public ID may be present in the binary, while OAuth token persistence remains exclusively in the platform credential store. See [configuration precedence and build commands](authentication.md).

Startup and hourly validation run in Rust independently of the webview. Identity, client ID, scopes, and expiry must validate before the account is exposed. Refresh preserves the validated account ID. Transient validation errors hide identity and retry after 60 seconds. Refresh occurs at known expiration, recoverable access-token validation rejection, or a Helix 401, and never blindly retries a one-use refresh token. Newly issued tokens are validated without recursive refresh. Secure deletion must be confirmed by an absent-entry read before rotation is dispatched. Normal shutdown cancels device polling, rejects queued/new auth work, and waits for an active rotation and secure-store write; process shutdown proceeds concurrently.

`CredentialStore` remains the Rust-only storage interface. `CredentialVault` serializes its blocking OS calls on blocking workers. Desktop uses Keychain, Credential Manager, or Secret Service; memory storage is for deterministic tests. A process-held filesystem lock prevents two instances using this application's configuration directory from rotating the same entry. Credentials are a single versioned secure-store record, separate from settings. There is no insecure fallback. Token types have no Debug/IPC serialization and owned token buffers zeroize on drop; networking/OS libraries may have their own temporary copies. See [authentication](authentication.md) for rotation and storage tradeoffs.

`TwitchHttp` owns one reqwest connection pool shared by OAuth and Helix. The Helix client owns its shared rate coordinator and bounded cache, with typed endpoint methods and no arbitrary endpoint/URL IPC. The cache has distinct live/metadata/category lifetimes; stale results and incomplete batches are explicit. Callers control each pagination step. A small internal clock helper accumulates elapsed time from monotonic and wall clocks for authentication, cache age and rate resets. System sleep counts even when monotonic time pauses; backward wall adjustments cannot rewind freshness or extend an observed deadline. Short waits remain Tokio timers. See [Helix contracts](helix.md).

React holds UI inputs and safe backend snapshots. It reconstructs auth from status/account commands after reload and discards late account responses after logout. The shell polls auth at most once per second after completion, reads account details once per public auth-session generation, and does not reload account state on navigation. The application playback hook independently polls Rust session snapshots at most once per second after completion, including when Watching is closed. A request revision discards polls predating a completed action. Reload reconstructs sessions from Rust; React only owns pending-request guards, panel visibility and a draft restart quality. Failed account reads retry after 60 seconds. Pending auth, cancellation, probe/launch, and each session's Stop have separate guards; the backend remains authoritative. There is no frontend Twitch API client or authoritative query cache.

Settings are strict version 2 JSON containing `streamlinkPath`, a player mode/optional executable/literal argument vector, and default quality. Version 1 from this app upgrades in memory while preserving its path and is written as version 2 only on a successful save. The directory comes from Tauri's `app_config_dir()`. Saves use a temporary file in the same directory and atomic replacement. Malformed schemas and unknown versions are rejected without overwriting the file. Values are validated at use and save; missing executable files produce typed diagnostics. No settings from the legacy GUI or prior identity namespace are imported. A probe failure leaves the previous settings unchanged.

Successful custom-path probes save the validated absolute path selected by the user, preserving stable symlinks across package upgrades. Discovery resolves its current target for each probe and launch; the resolved path is diagnostic output, not the persisted preference.

## Phase 2 shell and navigation

The compact sidebar exposes Following, Live, Categories and Search; account controls remain in the top bar. A small in-memory route union adds category and channel detail routes. No browser URL router or new component framework is needed for this desktop application. A bounded twelve-entry Back stack records route, scroll position and focused item; native buttons provide keyboard activation and visible focus. The minimum native window is 620 × 600; grids adapt and navigation becomes horizontal at smaller preview widths.

System/dark/light themes use CSS variables. The only new persistent frontend preference is appearance in local storage; no account, query, cursor or credential is persisted there. `DeveloperTools` retains the old screen and process actions, unmounting the browsing shell while open. Stream cards and live channel rows/details now provide a separate keyboard-accessible Watch action. Watching and playback settings are compact, scrollable panels; opening either leaves the browsing workspace mounted. Normal UI renders fixed typed-error messages rather than arbitrary backend error text.

## Browsing IPC and DTO boundary

| Command | Request | Response |
| --- | --- | --- |
| `list_followed_streams` | `BrowseRequest` | `PagedResult<StreamSummary>` |
| `list_followed_channels` | `BrowseRequest` | `PagedResult<ChannelSummary>` |
| `list_streams` | `BrowseRequest` | `PagedResult<StreamSummary>` |
| `list_categories` | `BrowseRequest` | `PagedResult<CategorySummary>` |
| `list_category_streams` | `EntityRequest` | `CategoryDetails` |
| `search_channels` | `SearchRequest` | `PagedResult<ChannelSummary>` |
| `search_categories` | `SearchRequest` | `PagedResult<CategorySummary>` |
| `get_channel` | `EntityRequest` | `ChannelDetails` |

`BrowseRequest` carries a public `sessionId`, an optional cursor, and an explicit refresh flag. Entity/search requests add an ID/query, never an arbitrary endpoint or URL. `AuthStatus.sessionId` is a public generation marker, not a credential or authority grant. Rust obtains an authenticated lease for that exact session before querying and pins every enrichment/retry to it. Logout or a later login cancels the original lease. React keys its whole browsing workspace by this marker, clearing all navigation snapshots even when the same user logs out and back in.

Thin command adapters acquire one of eight browse permits and invoke `helix::browse`. This bounds outstanding searches and rate-limit waiters without queuing unlimited IPC work. Authentication and process management have independent capacity. Query DTOs distinguish stream ID, broadcaster ID, login and display name. Optional category/description/language/image fields are explicit; DTOs exclude raw provider bodies, tokens, email and private account metadata. Errors are typed codes rendered through fixed user-facing messages.

Following channels enriches only the requested page with one user metadata batch and at most one live-status batch. Fresh positive live matches from the first followed-stream page reuse the existing backend cache; unseen IDs are still queried, since omissions in a paginated response never prove offline status. Explicit refresh bypasses live reuse. A successful complete stream response can establish offline state; network failures or incomplete responses produce unknown status and warnings. Partial metadata failure preserves follow identity and follow date. Authentication failures remain terminal. Channel details use the same distinction.

## Freshness, pagination and rendering bounds

The existing Rust cache remains authoritative: 15-second live data, 300-second user metadata, 3,600-second category metadata, at most 128 entries/8 MiB. Cross-view reuse uses the same session-scoped query keys and TTL checks, with no second cache. Refresh bypasses live/query cache entries; long-lived profile/category enrichment may still use its own fresh metadata entry. Result DTOs report network/cached/stale state, maximum source age and partial-detail warnings.

Each list command requests 30 items and returns an explicit cursor. React requests another page only on Load more, deduplicates by the correct entity ID, rejects repeated cursors and retains at most 10 pages/300 items per view. Refresh starts that view over. Its `ViewMemory` retains at most twelve view snapshots for navigation; it has no TTL, background refresh or independent freshness rules. Restored and accumulated snapshots are labeled Previous results; failed refresh keeps existing data with an update-failed message. Only Rust can return a fresh/cached result. Phase 2 does not automatically fall back to expired backend entries.

Search debounces for 350 ms, trims input, ignores empty queries and separates channel/category cursors. Editing the query immediately unmounts older results, so a late response cannot replace the new query even during debounce. Superseded IPC calls may finish under the existing HTTP/rate bounds and eight-query capacity; account cancellation terminates them at the backend. Request generations and unmount guards also protect refresh, pagination and account reads.

Shared `StreamList`/`StreamPreview`, category artwork and channel rows keep presentation consistent. Rust permits only Twitch CDN HTTPS image URLs and substitutes bounded dimensions (480 × 270 preview, 144 × 192 artwork, compact profiles). React loads images lazily, keeps aspect ratios reserved, uses empty alt text alongside labeled controls, and displays placeholders on failure. No image proxy, original-resolution fetcher or virtualization layer was introduced. Loading, empty, missing permission, unavailable, offline and network-error states remain distinct.
